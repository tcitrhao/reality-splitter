## 一、网站定位

Reality Splitter 是一个拆解信息的 Chrome 插件，也是一项持续迭代的个人 AI 产品实践。

官网只承担四件事：

1. 介绍产品。
2. 提供插件下载。
3. 记录产品迭代。
4. 沉淀 AI 产品思考。

### 文案原则

- 一屏只表达一件事。
- 先说产品，再说理念。
- 能用一句话说清楚，就不用两句。
- 不重复强调项目性质。
- AI 不提供最终答案，判断权留给人。

## 三、排版系统

这套排版遵循两组方法：

- 《The Elements of User Experience》：先明确页面目标与内容结构，再决定导航、布局和视觉。
- 《The Non-Designer's Design Book》：用亲密性、对齐、重复和对比建立稳定秩序。

### 页面目标

| 页面 | 用户任务 | 主要内容 |
| --- | --- | --- |
| 产品 | 理解产品并决定是否下载 | 定位、示例、流程 |
| 迭代 | 了解产品如何演进 | 版本、变化、学习 |
| AI 沉思录 | 发现并阅读文章 | 标题、摘要、正文 |
| 关于 | 理解项目立场 | 背景、原则 |

### 对齐

- 网站最大宽度：`960px`
- 列表与结构化内容：`760px`
- 长文阅读宽度：`680px`
- 元信息列：`112px`
- 桌面端所有页面共用同一条左对齐线
- 内容变宽时只向右扩展，不改变起点

### 重复

- 所有独立页面重复同一种页头结构
- 所有列表重复相同的元信息列、标题层级和分隔线
- 标题使用宋体，界面文字使用无衬线体，编号与状态使用等宽体
- 蓝色只用于链接、当前导航和键盘焦点

### 亲密性

- 标题与说明保持紧密
- 同一条记录内部紧密，不同记录用分隔线区分
- 页面级区块使用更大的垂直间距
- 摘要不与正文混排

### 对比

- 产品名称是全站最强标题
- 页面标题次之，列表标题再次之
- 正文使用主文字色，辅助说明和状态使用灰色
- 不依靠额外装饰制造层级

#### 拆解示例

> “重大利好已经确认，现在不上车就晚了。”

| 类型 | 内容 |
| --- | --- |
| 事实 | 文中没有给出可验证的数据来源 |
| 观点 | “重大利好”是结论性判断 |
| 情绪 | “不上车就晚了”在制造紧迫感 |
| 待核查 | 利好依据、时间范围和原始出处 |

| 03 | 再判断 | 保留决定权，也给自己多一点思考时间。 |

## 五、内容模板

### 产品迭代

```markdown
阶段：现在
版本：v0.0.0

标题：一句话概括本次变化

更新内容：
说明做了什么，以及为什么。

这一阶段的学习：
记录这次迭代真正学到的东西。
```

适合记录：

- 新增或删除了什么
- 为什么改变方向
- 用户反馈带来的调整
- 本阶段学到了什么
- 下一步准备验证什么

### AI 沉思录

```markdown
编号：01
状态：写作中 / 随笔 / 已发布

标题：文章讨论的核心问题

摘要：
用一至两句话说明文章内容。

Markdown 正文：

## 第一个部分

从一个具体问题开始。

## 第二个部分

写下观察、判断和仍未解决的问题。
```

建议每篇文章保持：

- 一个核心问题
- 一至两句摘要
- 三至五个正文小节
- 一个暂时结论或开放问题

## 六、维护与发布

### 使用内容后台

```bash
npm run studio
```

在“AI 沉思录”中：

1. 填写编号、状态和标题。
2. 摘要保持一至两句话。
3. 在“Markdown 正文”中编辑完整文章。
4. 发布后，有正文的文章会自动获得独立阅读页。

### 发布到官网

后台发布只更新本地文件。将变更提交并推送到 `main` 后，GitHub Pages 才会更新公网网站。

### 发布前检查

- 首页只有一个下载入口
- 页面没有重复栏目标签
- 新文章有简短摘要
- 完整内容写在 Markdown 正文中
- Markdown 标题、列表、表格与链接显示正常
- 手机和桌面端均完成预览
