01 · MODEL

模型不是产品，也不是万能员工

大语言模型是在上下文条件下生成后续内容的概率模型。它能表现出理解、推理、生成和规划，但“表现得会”不等于“稳定正确地完成”。

模型相对擅长

  • 语义理解、分类和信息抽取
  • 摘要、翻译、改写和格式转换
  • 开放式草稿、代码和方案生成
  • 从材料中归纳模式和线索
  • 有限推理、拆步骤和工具选择

模型天然不拥有

  • 可靠的实时事实和权威证据
  • 用户文件、邮箱和数据库权限
  • 跨会话可靠且可治理的记忆
  • 精确计算和确定性执行保证
  • 长任务状态、责任与后果承担
模型：生成“可能正确的下一步”
产品：让正确上下文进入，让动作可执行，让错误可发现，让用户可控制
02 · FRAMEWORK

用户体验五要素，升级成 AI 产品框架

从底层战略到表层表现，每一层都需要同时回答用户问题与模型问题。

战略层 Strategy为谁解决什么问题？成功是什么？为什么需要 AI？失败代价多高？
范围层 Scope做什么、不做什么？模型、检索、工具、记忆如何分工？
结构层 Structure用户任务怎样流转？一次生成、固定工作流，还是 Agent Loop？
框架层 Skeleton信息与控件如何组织？如何显示来源、过程、Diff、确认和失败？
表现层 Surface用户看到和感受到什么？如何避免把概率结果包装成确定事实？
正确顺序：用户任务与失败代价 → AI 能力合同 → 人机工作流 → 控制与反馈界面 → 视觉与语言。不要从“加个聊天框”开始。
03 · BOUNDARY

需求不是都交给模型：系统要补齐边界

用户需要模型单独为何不够产品系统应该增加
最新事实参数知识可能过时搜索、数据库、RAG、引用与时间戳
精确计算语言生成不是计算器代码执行、计算器、数据库聚合
长期记忆上下文窗口不是记忆库结构化存储、检索、编辑与删除
修改文件或发消息模型没有天然权限工具、权限、沙箱、确认、日志、撤销
长时间多步任务容易偏航、遗忘或循环状态机、检查点、重试、预算和终止条件
高风险判断可能幻觉且不承担后果权威来源、人工复核、审计与责任边界
稳定结构输出生成具有概率性Schema、校验、重试、兜底与 Eval

06 · PRODUCT CANVAS

Reality Splitter 五要素画布

战略层

用户任务：在想立刻相信、转发、反击或 all-in 时，恢复判断空间。

产品目标：区分原文与推断，恢复多假设，把大动作变成小验证。

反指标：不要追求分析越多、停留越久、输出越长。

范围层

做：主动选择、文本分层、中性改写、替代解释、小实验。

不做：全流扫描、心理诊断、人格判断、无来源事实核查、自动行动。

能力合同：分析表达结构，不凭原文确认外部真假。

结构层

选择内容 → 快速拆解 → 降刺激 / 替代解释 / 小实验 → 用户决定跳过、保存、验证或小步行动。

架构选择：固定工作流优先，不做开放 Agent。

框架层

第一屏显示原文和总体提醒；第二层显示事实/观点/推断；第三层显示证据限制与替代解释；最后才给行动选项。

显式区分“仅基于原文”和“已联网核查”。

表现层

低饱和、短内容、默认折叠细节；使用“可能、暗示、仅凭原文无法判断”；避免“危险、有毒、你被操控了”等强刺激和伪诊断表达。

克制感不是装饰，而是产品功能。

07 · PM CHECKLIST

每个 AI 需求进入开发前，回答七问

用户任务是什么？写清情境、目标和想改变的状态，不写“用 AI 分析”。
为什么需要模型？规则、搜索或数据库能稳定解决时，不要强行用大模型。
模型需要什么上下文？最少、相关、可授权、可追溯。
需要哪些外部能力？区分知识、搜索、计算、工具、记忆和权限。
输出合同是什么？Schema、长度、不确定性、禁止项和空结果。
谁验证、如何恢复？人审、测试、引用、Diff、撤销、重试或降级。
怎样证明它变好了？先定义 Eval，再换 Prompt 或模型；记录正确性、完整性、克制程度、延迟、失败率、Token 和费用。
08 · DECISION

选择满足需求的最低自主性

任务特征推荐架构代表场景
低风险、固定输入和输出单次调用 + Schema分类、改写、Reality Splitter 快速模式
需要私有材料但不行动RAG / 文件检索 + 生成企业问答、合同检索
需要最新信息搜索/数据库 + 引用新闻研究、事实核查
多步骤但路径固定Workflow / 状态机报销审核、内容流水线
路径不固定且工具可验证Agent Loop + SandboxCodex 工程任务
开放目标、跨网页/应用Computer Agent + Take OverManus 式委托
企业多岗位、知识和权限Orchestrator + Skills/MCP + GovernanceWorkBuddy 式办公工作台
高风险外部动作强制人审 + 审计 + 回滚支付、发布、医疗/法律关键决定

自主性越高，演示通常越惊艳；同时成本、失败面、权限风险和评测难度也越高。

09 · REALITY CHECK

六个“AI 什么都能做”的常见误区

一次成功 ≠ 稳定能力

一次是 Demo；跨输入、版本和网络仍可靠才是产品。

知道很多 ≠ 当前事实

模型记忆、搜索结果与权威证据是三回事。

能规划 ≠ 能完成

还需要工具、权限、状态、恢复和验证。

记得多 ≠ 更懂用户

错误记忆与过度收集会降低质量和信任。

多 Agent ≠ 更高级

角色边界和汇总验证不清时，只会增加成本与错误传播。

大模型 ≠ 自动修复产品

错误上下文、模糊目标和糟糕交互仍然存在。

10 · ROADMAP

用 Reality Splitter 完成四阶段学习

阶段 1

垂直 AI Workflow

完善 Context → Prompt → Schema → UI；建立 30–50 条 Eval；比较模型、Prompt、延迟与成本；标记模型和兜底来源。

阶段 2

有来源的能力

增加按需检索；建立 Claim、Evidence、Source、Timestamp；明确文本分析与外部核查两个模式。

阶段 3

轻量个性化

只保存用户可见、可编辑、可删除的产品偏好；不用隐蔽心理画像；用 Eval 证明个性化价值。

阶段 4

最后才考虑 Agent

只有出现“自动找来源 → 比较 → 生成验证卡 → 保存/提醒”的真实需求，才引入工具选择、状态、重试和确认点。

最终心智模型

模型决定能力上限，上下文决定它看见什么，工具决定它能做什么，工作流决定它怎样持续做，界面决定用户怎样理解和控制，评测与治理决定产品能否被长期信任。

产品经理真正要学会的不是“给所有需求加 AI”，而是判断：这是语言问题、知识问题、数据问题、执行问题、记忆问题，还是责任问题？
