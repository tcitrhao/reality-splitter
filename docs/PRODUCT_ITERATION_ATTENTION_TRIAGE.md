# Reality Splitter 产品迭代：注意力分诊

## 这次迭代解决什么

当前插件最容易被替代的部分是：

```text
选中文本 -> 固定 Prompt -> 模型分析 -> 展示结果
```

它减少了复制粘贴路径，但仍然更像一个快捷工具。结合最近的 AI 产品架构学习，下一步应该把产品推进到：

```text
帮助用户判断这条信息应该怎样处理
```

也就是从“生成分析”升级到“注意力分诊”。

## 产品原则

成熟 AI 产品不是只提高模型回答概率，还要：

```text
1. 提高有用结果出现的概率
2. 提高错误和不确定性被发现的概率
3. 降低错误行动的损失
```

Reality Splitter 对应到用户现场，就是先回答：

```text
这条内容值得继续占用注意力吗？
应该跳过、扫读、验证、保存，还是延迟行动？
```

## 新增能力

短文拆解结果新增 `attentionTriage`：

```ts
{
  recommendedAction: "skip" | "skim" | "verify" | "save" | "delay";
  attentionCost: "low" | "medium" | "high";
  reason: string;
  nextStep: string;
}
```

五种动作含义：

| 动作 | 含义 |
|---|---|
| `skip` | 和当前目标弱相关，或高刺激低证据，建议跳过 |
| `skim` | 可以低成本扫读，不需要深度处理 |
| `verify` | 涉及重大事实、传闻、投资、职业风险，先验证 |
| `save` | 有长期学习或研究价值，值得保存 |
| `delay` | 情绪强、诱导立刻行动，先延迟 |

## 为什么先做这个

这次迭代不引入新的 Agent、联网检索或 Memory，因为那些会显著增加不稳定性。先做注意力分诊有三个好处：

```text
1. 提升产品定位：从文本拆解工具变成信息处理工作流
2. 降低替代风险：平台可以复制“拆解按钮”，但较难复制用户侧的注意力协议
3. 建立未来闭环：后续可以记录用户选择，形成 Eval 和反馈数据
```

## 下一步建议

后续可以加一个轻量反馈区：

```text
这次建议是否帮你节省注意力？
[跳过了] [去验证] [保存了] [没帮助]
```

这些反馈会成为 Reality Splitter 的第一批真实产品资产，而不是只依赖 Prompt 感觉调参。
